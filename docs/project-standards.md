## 1 Cursor / LLM "Rules"

_All rules defined here should also live in `.cursorrules` at repo root. Keep that file < 500 lines to avoid truncation._

### 1.1 Repository Context (Static Block)

```md
# Repository Context

• Backend – `backend/` (Python 3.12, FastAPI)
• Frontend – `frontend/` (React 18, TypeScript strict)
• Infrastructure – `infra/` (Docker Compose, deploy scripts)
• Sample Data - `sample_data/` (for testing)
```

### 1.2 Global Behaviour Rules

```md
# Behaviour

1. Explain intent in ≤3 sentences **before** code edits.
2. Update or create tests **and** docs for every logic change.
3. All modified files must pass `pre-commit run --all-files` locally.
4. `sample_data/` must behave identically to live ADS-B (env-switch only).
5. If WebSocket payload schema changes, bump `ws_schema.yaml` and PRD section.
6. Do not remove existing functionality unless explicitly told.
```

### 1.3 File-Type-Specific Prompts

```md
# When editing \*.py

- Use Google-style docstrings (Args / Returns / Raises / Example).
- Preserve type hints.
- Prefer `pydantic.BaseModel` for structured data.
- Limit functions to 50 logical lines; extract helpers if larger.
- In FastAPI routes use `async def`; avoid blocking I/O.

# When editing _.tsx / _.ts

- Run `npm run lint -- --fix` before commit.
- Use Prettier-formatted, ESLint-clean code.
- Functional components & React hooks only.
- Props must be fully typed; forbid `any`.
- Style with Tailwind; avoid inline styles except dynamic transforms.

# When editing \*.md / docs

- Wrap at 80 chars except for long URLs.
- Use fenced blocks with language tags for code samples.
```

### 1.4 Context & Documentation Upkeep

```md
# Context Refresh

- When README sections change, regenerate the "Context for LLMs" bullet list.
- After API change run `make openapi` to regenerate `.docs/api_openapi.yaml` **and commit**.
- Record major architectural decisions in a new ADR file under `ADR/`.
- Each new TODO/FIXME in code requires matching entry in `TECH_DEBT.md`.
```

### 1.5 Reusable Prompt Macros Reference (`.cursor/prompts/`)

- Use `@prompts/debug-template` for debugging issues.
- Use `@prompts/refactor-small` for localized refactoring.
- Use `@prompts/feature-boilerplate` for adding new FastAPI routes.

## 3 Documentation Framework

_Inspired by ReadMe.LLM research ([arxiv.org/abs/2504.09798](https://arxiv.org/abs/2504.09798))._

### 3.1 File Map

```
README.md              # Top-level: purpose, quick-start, project map (LLM-friendly)
backend/README.md      # Backend API run & test instructions
frontend/README.md     # Frontend UI dev server, env vars
TECH_DEBT.md           # Accumulated compromises & TODOs log
ADR/                   # Architecture Decision Records (e.g., ADR/0001-initial.md)
docs/
  project-standards.md # This file
  api_openapi.yaml     # Autogenerated API spec (commit on breaking changes)
  ws_schema.yaml       # WebSocket message schema
  diagrams/            # Architecture diagrams (e.g., architecture.drawio)
sample_data/           # Sample data (e.g., adsb_1min.sbs, airports_min.json)
LICENSE                # MIT License file
.env.example           # Example environment variables
.cursor/rules/           # LLM interaction rules (mirror of Section 1)
.cursor/prompts/       # Reusable prompt templates (see Section 6)
examples/              # End-to-end usage scripts
```

### 3.2 README Sections (LLM-friendly Structure)

1.  **Purpose:** One-paragraph elevator pitch.
2.  **TL;DR Usage:** `docker compose up` snippet.
3.  **Context for LLMs:** Bulleted summary of architecture & key files (<150 words).
4.  **Modules:** Table mapping folders ➔ responsibility.
5.  **Endpoints / Messages:** Link to spec files (`api_openapi.yaml`, `ws_schema.yaml`), plus one code example each.
6.  **Common Tasks:** How to start servers, run tests, populate env vars.
7.  **FAQ & Gotchas:** Known tricky bits, common issues, pointers.

### 3.3 TECHDEBT.md Template

```md
## ⛳ Item: [Brief Title of Debt/TODO]

- **Context:** [Where is this? What led to this shortcut/issue?]
- **Potential issues:** [What problems might this cause later?]
- **Why accepted:** [Reason for not fixing immediately (e.g., MVP deadline)]
- **Next step:** [How to resolve? Link to issue tracker if applicable.]
- **Code Ref:** `path/to/file.py#L123` (Optional: Link to specific code line)

---
```

_Curate this list during PR reviews. CI should fail if a `TODO` or `FIXME` comment exists in code without a corresponding entry here._

### 3.4 OpenAPI & WS Schemas Policy

- API spec (`.docs/api_openapi.yaml`) should be auto-generated (e.g., via a `make openapi` command).
- WS schema (`.docs/ws_schema.yaml`) should be manually maintained or generated if tooling allows.
- **Commit updated schema files whenever a breaking change is merged into `main`.** This keeps LLM agent context accurate.

## 4 Development Workflow & Governance

| Topic               | Decision                                                                                   |
| ------------------- | ------------------------------------------------------------------------------------------ |
| Branching           | **Trunk-based:** Feature branches off `main`, short-lived PRs into `main`.                 |
| Commits             | **Conventional Commits** (`feat:`, `fix:`, `docs:`, `chore:`, etc.).                       |
| Releases            | Tag `vX.Y.Z` on `main` following **SemVer** for repo & API versions.                       |
| Licence             | **MIT** (`LICENSE` file at repo root).                                                     |
| Mock ADS-B          | Controlled by `FAKE_ADSB=1` env flag (backend restart toggles). Frontend is agnostic.      |
| Acceptance Criteria | Defined per task/issue. Consider adding a QA checklist (`qa-acceptance.md`).               |
| PR Template         | Use a standard template: Summary, Context/Ticket, Checklist (Tests, Docs, Rules updated?). |

## 5 Additional Up-Front Practices

| Practice                       | Rationale                                                              |
| ------------------------------ | ---------------------------------------------------------------------- |
| **ADR Folder**                 | Makes architectural decisions explicit; aids LLM understanding.        |
| **OpenAPI/WS Schema in Repo**  | Allows LLMs to reference schemas for accurate examples/requests.       |
| **`examples/` Directory**      | Provides executable documentation and integration test cases.          |
| **Docstring Examples Tested**  | Use `pytest --doctest-modules` to ensure examples stay valid.          |
| **`llm_context.txt` Snapshot** | (Optional) Machine-readable context summary, regenerated periodically. |
| **`sample_data/` Directory**   | Enables local/CI testing without live hardware/network feeds.          |
| **Pre-commit Hooks**           | Enforce formatting (Black, Prettier), linting (Ruff, ESLint), etc.     |

````
### 6.3 `feature-boilerplate.md`
```md
<!-- Cursor Feature Boilerplate Template -->
### Goal
Implement new FastAPI route **`<METHOD> /api/vX/<resource>`**.

### Deliverables
1. **Pydantic model(s)** – request & response in `backend/schemas/<resource>.py`.
2. **Router function** in `backend/routes/<resource>.py`.
3. **Service logic** (if needed) in `backend/services/<resource>.py`.
4. **Unit test** in `tests/backend/<area>/test_<action>.py`.
5. **OpenAPI** auto-regen (`make openapi`).
6. **README snippet** under *Endpoints* section (if significant).

### Steps
- [ ] Create/extend Pydantic schema(s).
- [ ] Implement route logic (`async def`) in router.
- [ ] Implement business logic in service layer.
- [ ] Add Swagger example/description in route docstring.
- [ ] Write positive + negative/edge-case unit tests.
- [ ] Run `pre-commit run --all-files`.
- [ ] Run `make openapi` and review changes.
- [ ] Commit updated `.docs/api_openapi.yaml`.

```python
# Example Route Stub (in backend/routes/items.py)
from fastapi import APIRouter, Depends, HTTPException, status
from sqlalchemy.orm import Session
from backend.database import get_db
from backend.schemas.item import ItemCreate, ItemOut
from backend.services.item_service import create_new_item

router = APIRouter()

@router.post("/items", response_model=ItemOut, status_code=status.HTTP_201_CREATED)
async def create_item_endpoint(
    item_in: ItemCreate,
    db: Session = Depends(get_db)
):
    """
    Create a new item.

    - **item_in**: Item data to create.
    - **Returns**: The newly created item.
    """
    try:
        new_item = create_new_item(db=db, item_create=item_in)
        return new_item
    except Exception as e: # Be more specific in real code
        raise HTTPException(status_code=status.HTTP_400_BAD_REQUEST, detail=str(e))

````
